# Version C — service feature layout

An asymmetric architectural hero leads into a sticky service index. The five
services use real, keyboard-operable tabs rather than repeating identical cards.
On mobile, the index becomes a horizontal scroll area. Direct links reveal the
corresponding service and the selected service survives language switching.
Without JavaScript, every service remains readable.

The process is arranged as editorial rows and the supplied qualifications form a
horizontal proof rail. The current orange, mineral blue, ivory, original logo,
fonts, bilingual copy, offers and shared interactions are retained. No invented
client logos, statistics or feedback are introduced.

```sh
npm run build:c
```

Open `design-c/dist/index.html` or `design-c/dist/de/index.html`. This is a standalone
comparison build, separate from production. The common builder is
`../design-experiments/build.cjs`; variant behaviour is in `interactions.js`.

See `../DESIGN-COMPARISON.md` for all versions, verification and the documented
owner-selected white-on-bright-orange contrast exception.
